# راهنمای بارگذاری سؤال در پنل مدیریت سی‌ام‌اس

این راهنما برای کسی نوشته شده که فقط به پنل وب مدیریت سی‌ام‌اس دسترسی دارد و هیچ دسترسی خط فرمانی به سرور ندارد.
همه‌ی فایل‌های لازم در پوشه‌ی زیر قرار دارند:

```
eviction/cms_upload/
```

محتوای این پوشه:

```
statement.pdf            (English statement, language code: en)
statement-fa.pdf         (Persian statement, language code: fa)
tests.zip                (77 tests = 154 files)
attachments/sample-01.in
attachments/sample-01.out
score_type.txt           (GroupMin parameters to paste)
task_settings.txt        (all values in one place)
optional_checker/checker (optional, static binary) + checker.cpp
sanity_solutions/        (solutions for sanity testing + EXPECTED_SCORES.txt)
verify_score_type.py     (regex verification script, already run: all OK)
```

نکته: برچسب دکمه‌ها و فیلدها در نسخه‌های مختلف سی‌ام‌اس ممکن است کمی متفاوت باشد. برچسب‌های این راهنما مطابق نسخه‌های ۱٫۴ و ۱٫۵ است.

---

## ۱. ساختن سؤال

۱. وارد پنل مدیریت شوید. در منوی سمت چپ، زیر بخش زیر:

```
Tasks
```

روی این گزینه کلیک کنید:

```
Create new task...
```

۲. در فیلد زیر:

```
Name
```

این مقدار را بنویسید:

```
eviction
```

۳. در فیلد زیر:

```
Title
```

این مقدار را بنویسید:

```
Express Eviction
```

۴. روی دکمه‌ی زیر کلیک کنید تا سؤال ساخته شود و صفحه‌ی ویرایش سؤال باز شود:

```
Create
```

## ۲. بارگذاری صورت سؤال

در صفحه‌ی سؤال، به بخش زیر بروید:

```
Statements
```

۱. روی این پیوند کلیک کنید:

```
Add statement
```

۲. در فیلد کد زبان این مقدار را بنویسید:

```
fa
```

۳. فایل زیر را انتخاب کنید و دکمه‌ی ارسال را بزنید:

```
cms_upload/statement-fa.pdf
```

۴. همین کار را یک بار دیگر برای صورت انگلیسی تکرار کنید. کد زبان:

```
en
```

فایل:

```
cms_upload/statement.pdf
```

۵. در صفحه‌ی سؤال، در فیلد زیر زبان‌های اصلی را مشخص کنید تا به شرکت‌کنندگان به‌طور پیش‌فرض نمایش داده شود:

```
Primary statements
```

مقدار پیشنهادی:

```
["fa", "en"]
```

## ۳. بارگذاری پیوست‌ها

در صفحه‌ی سؤال، در بخش زیر:

```
Attachments
```

روی این پیوند کلیک کنید:

```
Add attachment
```

و دو فایل زیر را یکی‌یکی بارگذاری کنید:

```
cms_upload/attachments/sample-01.in
```

```
cms_upload/attachments/sample-01.out
```

این سؤال گریدر یا فایل کمکی برای شرکت‌کننده ندارد؛ فقط مثال پیوست می‌شود.

## ۴. تنظیمات کلی سؤال و مجموعه‌داده

### ۴-۱. تنظیمات امتیازدهی و بازخورد (در همان صفحه‌ی سؤال)

حالت امتیاز را روی حالت جمع بهترین امتیاز هر زیرمسئله بگذارید. فیلد:

```
Score mode
```

مقدار:

```
Use the sum over subtasks of the best result for that subtask across submissions (IOI 2017-)
```

اگر این گزینه در نسخه‌ی شما نیست، این گزینه را انتخاب کنید:

```
Use best among submissions (IOI 2013-2016)
```

سطح بازخورد را کامل بگذارید. فیلد:

```
Feedback level
```

مقدار:

```
Full
```

توکن‌ها را غیرفعال کنید. فیلد:

```
Token generation mode
```

مقدار:

```
Disabled
```

دقت امتیاز. فیلد:

```
Score precision
```

مقدار:

```
0
```

در پایین صفحه حتماً روی دکمه‌ی زیر کلیک کنید تا تغییرات ذخیره شود:

```
Update
```

### ۴-۲. مجموعه‌داده

در صفحه‌ی سؤال، در بخش زیر یک مجموعه‌داده‌ی فعال به‌طور خودکار ساخته شده است:

```
Datasets
```

تنظیمات زیر را برای همان مجموعه‌داده وارد کنید.

محدودیت زمان، به ثانیه. فیلد:

```
Time limit
```

مقدار:

```
1
```

محدودیت حافظه، به مبی‌بایت. فیلد:

```
Memory limit (MiB)
```

مقدار:

```
256
```

نوع سؤال. فیلد:

```
Task type
```

مقدار:

```
Batch
```

گزینه‌های این نوع سؤال:

گزینه‌ی کامپایل:

```
Compilation: Submissions are self-sufficient
```

نام فایل‌های ورودی و خروجی: هر دو فیلد را **خالی** بگذارید تا ورودی و خروجی استاندارد استفاده شود.

```
I/O (filenames): input = (empty), output = (empty)
```

روش مقایسه‌ی خروجی، در بخش بعدی توضیح داده شده است.

نوع امتیازدهی. فیلد:

```
Score type
```

مقدار:

```
GroupMin
```

پارامترهای امتیازدهی. فیلد:

```
Score parameters
```

دقیقاً متن زیر را کپی و جای‌گذاری کنید. این متن در فایل زیر هم هست:

```
cms_upload/score_type.txt
```

```
[[0, "^0-01$"], [6, "^1-[0-9]+$"], [14, "^(0-01|2-[0-9]+)$"], [18, "^(0-01|3-[0-9]+)$"], [17, "^[14]-[0-9]+$"], [45, "^[0-9]+-[0-9]+$"]]
```

جدول زیرمسئله‌ها برای بررسی:

| زیرمسئله | امتیاز | آزمون‌ها | محدودیت |
|:---:|:---:|:---:|:---:|
| ۰ | ۰ | ۱ آزمون | مثال |
| ۱ | ۶ | ۱۰ آزمون | ارتفاع برابر ۱ |
| ۲ | ۱۴ | ۱۶ آزمون | حداکثر ۱۲ خانه‌ی مسکونی |
| ۳ | ۱۸ | ۱۶ آزمون | جواب حداکثر ۱ |
| ۴ | ۱۷ | ۲۱ آزمون | ارتفاع حداکثر ۲ |
| ۵ | ۴۵ | ۷۷ آزمون | کامل |

در پایین صفحه دکمه‌ی زیر را بزنید:

```
Update
```

## ۵. بررسی‌کننده و روش مقایسه‌ی خروجی

جواب این سؤال یک عدد صحیح **یکتا** است؛ بنابراین مقایسه‌ی ساده‌ی خروجی با نادیده گرفتن فاصله‌ها کافی است و **نیازی به بررسی‌کننده نیست**.

### روش پیشنهادی: مقایسه‌ی پیش‌فرض

در گزینه‌های نوع سؤال، روش مقایسه را روی این گزینه بگذارید:

```
Output evaluation: Outputs compared with white diff
```

در این حالت هیچ فایلی در بخش زیر لازم نیست:

```
Managers
```

### روش جایگزین و اختیاری: بررسی‌کننده‌ی اختصاصی

اگر به هر دلیلی خواستید از بررسی‌کننده استفاده کنید، نتیجه دقیقاً یکسان خواهد بود.

۱. روش مقایسه را روی این گزینه بگذارید:

```
Output evaluation: Outputs are compared by a comparator
```

۲. در بخش زیر:

```
Managers
```

روی این پیوند کلیک کنید:

```
Add manager
```

۳. این فایل را انتخاب کنید. این فایل یک برنامه‌ی ایستای ۶۴ بیتی لینوکس است و به هیچ کتابخانه‌ای نیاز ندارد:

```
cms_upload/optional_checker/checker
```

نام فایل در سرور باید دقیقاً این باشد، بدون پسوند:

```
checker
```

این برنامه طبق پروتکل سی‌ام‌اس این‌گونه اجرا می‌شود و امتیاز را در خروجی استاندارد و پیام را در خروجی خطا چاپ می‌کند:

```
checker input correct_output contestant_output
```

## ۶. بارگذاری گروهی آزمون‌ها

در صفحه‌ی سؤال، در بخش مجموعه‌داده، روی این پیوند کلیک کنید:

```
Add multiple testcases
```

۱. فایل زیر را انتخاب کنید:

```
cms_upload/tests.zip
```

۲. الگوی فایل ورودی. فیلد:

```
Input template
```

مقدار:

```
*.in
```

۳. الگوی فایل خروجی. فیلد:

```
Output template
```

مقدار:

```
*.out
```

۴. گزینه‌ی زیر را **تیک نزنید**:

```
Public
```

۵. اگر قبلاً آزمونی بارگذاری کرده‌اید و می‌خواهید جایگزین شود، این گزینه را تیک بزنید:

```
Overwrite
```

۶. دکمه‌ی ارسال را بزنید:

```
Submit
```

### بررسی تعداد آزمون‌ها

پس از بارگذاری، در فهرست آزمون‌ها باید دقیقاً **۷۷** آزمون دیده شود. نام آزمون‌ها به این شکل است:

```
0-01
1-01 ... 1-10
2-01 ... 2-15
3-01 ... 3-15
4-01 ... 4-11
5-01 ... 5-25
```

عدد اول شماره‌ی زیرمسئله‌ای است که آزمون اولین بار در آن آمده و عدد دوم شماره‌ی آزمون است. آزمون‌های زیرمسئله‌های کوچک‌تر از طریق عبارت‌های منظم در زیرمسئله‌های بزرگ‌تر هم شمرده می‌شوند.

### عمومی و خصوصی

پیشنهاد: فقط آزمون مثال را عمومی کنید. در فهرست آزمون‌ها، کنار آزمون زیر، گزینه‌ی عمومی را تیک بزنید:

```
0-01
```

بقیه‌ی آزمون‌ها خصوصی بمانند. چون سطح بازخورد کامل است، شرکت‌کننده باز هم امتیاز هر زیرمسئله را می‌بیند.

C++17 / g++

## ۸. آزمایش درستی تنظیمات

یک کاربر آزمایشی بسازید، او را به مسابقه اضافه کنید، با او وارد صفحه‌ی شرکت‌کنندگان شوید و فایل‌های پوشه‌ی زیر را ارسال کنید:

```
cms_upload/sanity_solutions/
```

امتیاز مورد انتظار هر فایل:

| فایل | امتیاز مورد انتظار | توضیح |
|---|:---:|---|

| `p_h1.cpp` | ۶ | فقط زیرمسئله‌ی ۱ |
| `brute.cpp` | ۱۴ | فقط زیرمسئله‌ی ۲، بقیه زمان زیاد |

اگر امتیاز راه‌حل اصلی کمتر از ۱۰۰ بود یا یکی از امتیازهای بالا متفاوت بود، بخش بعدی را ببینید.

## ۹. رفع اشکال

### بررسی‌کننده اجرا نمی‌شود یا خطای اجرای ارزیابی

اگر این خطا را دیدید:

```
Execution failed
```

یا ارزیابی با خطای سیستمی متوقف شد:

۱. ساده‌ترین راه: روش مقایسه را به حالت پیش‌فرض برگردانید و بررسی‌کننده را حذف کنید:

```
Output evaluation: Outputs compared with white diff
```

۲. اگر بررسی‌کننده می‌خواهید، مطمئن شوید نام فایل در بخش زیر دقیقاً همین است، بدون پسوند و بدون فاصله:

```
checker
```

۳. فقط فایل اجرایی ایستا را بارگذاری کنید، نه فایل منبع را. فایل درست:

```
cms_upload/optional_checker/checker
```

۴. پس از هر تغییر، ارسال‌ها را دوباره ارزیابی کنید. در صفحه‌ی سؤال یا ارسال این دکمه را بزنید:

```
Re-evaluate
```

### عبارت منظم اشتباه و امتیاز صفر

اگر راه‌حل اصلی همه‌ی آزمون‌ها را درست جواب داده ولی امتیاز صفر یا کمتر از ۱۰۰ گرفته:

۱. مطمئن شوید نوع امتیازدهی این است:

```
GroupMin
```

۲. متن پارامترها را دوباره و دقیقاً از فایل زیر کپی کنید؛ گیومه‌ها باید گیومه‌ی ساده‌ی انگلیسی باشند و هیچ فاصله یا نویسه‌ی اضافه‌ای در ابتدا یا انتها نباشد:

```
cms_upload/score_type.txt
```

۳. نام آزمون‌ها در فهرست آزمون‌ها باید دقیقاً به این شکل باشد. اگر نامی مثل نمونه‌ی دوم دیدید، الگوها اشتباه وارد شده‌اند:

```
درست:  1-05
غلط:   1-05.in   یا   input.1-05
```

۴. پس از اصلاح، دکمه‌ی زیر و سپس ارزیابی دوباره را بزنید:

```
Update
```

### اشتباه در واحد محدودیت حافظه

فیلد حافظه در پنل بر حسب مبی‌بایت است:

```
Memory limit (MiB)
```

مقدار درست:

```
256
```

مقادیر غلط رایج:

```
268435456      (bytes - wrong)
262144         (KiB - wrong)
```

اگر راه‌حل اصلی خطای حافظه یا خطای زمان اجرا گرفت، این مقدار را بررسی و اصلاح کنید و دوباره ارزیابی کنید.

### ناهماهنگی نام فایل‌ها در فایل زیپ

اگر پس از بارگذاری تعداد آزمون‌ها صفر یا کمتر از ۷۷ بود:

۱. الگوها باید دقیقاً این‌ها باشند و نه مقادیر پیش‌فرض پنل:

```
Input template:  *.in
Output template: *.out
```

مقادیر پیش‌فرض پنل که باید پاک شوند:

```
input.*
output.*
```

۲. فایل زیپ را باز نکنید و دوباره نسازید؛ همان فایل اصلی را بارگذاری کنید. فایل‌ها در ریشه‌ی آرشیو هستند و هیچ پوشه‌ای ندارند.

۳. اگر آزمون‌های قبلی تکراری یا اشتباه هستند، یا آن‌ها را در فهرست آزمون‌ها انتخاب و حذف کنید، یا هنگام بارگذاری این گزینه را تیک بزنید:

```
Overwrite
```

### راه‌حل اصلی زمان زیاد می‌گیرد

راه‌حل اصلی روی بزرگ‌ترین آزمون کمتر از ۳۰ میلی‌ثانیه طول می‌کشد. اگر خطای زمان دیدید، احتمالاً محدودیت زمان اشتباه وارد شده است. مقدار درست بر حسب ثانیه:

```
1
```

## پیوست: راه‌حل سؤال

خانه‌های مسکونی که تخلیه نمی‌شوند، رأس‌های گوشه‌ی خود را مسدود می‌کنند. مسیر وجود ندارد اگر و تنها اگر زنجیره‌ای از خانه‌های مسکونی باقی‌مانده از ضلع چپ یا پایین به ضلع بالا یا راست برسد، به‌طوری که هر دو خانه‌ی پشت سر هم در زنجیره در هر دو محور فاصله‌ی حداکثر ۲ داشته باشند. پس جواب برابر کمینه‌ی برش رأسی بین این دو گروه ضلع است و با شار بیشینه محاسبه می‌شود. پیچیدگی زمانی برای این ابعاد بسیار کوچک است.
